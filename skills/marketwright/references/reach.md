# Procedure: communities, press, creators, devlogs, post calendar

Output: `reach-<slug>.md` with the places, the drafts and the calendar. The user posts and sends; you draft. Read [../kb/ethics.md](../kb/ethics.md) and [../kb/data.md](../kb/data.md).

## Communities

1. `MKW communities --genre <genre> --general`. Keep the places where the game's players gather and devs are welcome; drop any whose self-promotion is banned or where AI content is rejected when the game uses it.
2. For each kept place: its rule (with the check date), the format that fits (flair, weekly thread such as Screenshot Saturday, feedback thread), and what the user does there besides posting (answer questions, give feedback). Tell the user to read the rules page on the day; mark rows not read live.
3. Each post draft says who made it ("I'm the dev"), shows the game as it plays, asks a real question or shares something useful (a lesson, a GIF of a fix), and fits that place. No cross-posting the same text everywhere.

## Press kit

The contents list in kb/data.md. Hosted page: sitewright, or presskit.html. Include AI use and Early Access status plainly.

## Creators and press

1. Build the list from who covers the closest games (their recent videos or articles), not from follower counts. Each row: name, channel or outlet, the similar game they covered and when, contact route from their own page, language.
2. Keys: Steam keys or Curator Connect, no condition on the verdict, logged; vet requesters (fake journalists ask for keys).
3. Email draft: their name, the similar game they covered, the hook in one line, one GIF or trailer link, the key offer with no strings, embargo date if any, one line asking them to disclose the free copy. Short; never a template blast.
4. Tools: Keymailer, Lurkit (kb/data.md, with their status), Steam Curator Connect.

## Devlogs and the post calendar

1. Cadence the user can keep. One home for long posts (Steam news, itch devlog, a blog), short clips on one or two social platforms the user likes.
2. Calendar table: date, place, format, draft, asset needed, done. Tie peaks to the plan's dates (announcement, playtest, demo, Next Fest, launch).
3. Ethics check: save, run `MKW ethics reach-<slug>.md`, fix every flag.
